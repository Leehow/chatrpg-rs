# 模组"文档→图谱"抽取 —— 方法与开源项目调研（2026-06-09）

> 调研动机：当前 ModuleGraph 抽出来是"点+实体索引"，**scene→scene 的边全空（P1）**、长文档**骨架完整度 run-to-run 飘且严重欠抽（P2，Homecoming 3 vs 24）**、跨页实体去重（P3）、关系抽取（P4）。本文调研业界方法与 OSS，给出对症我们四个痛点的可借鉴打法。

## 0. 头号结论

**业界没有现成的"PDF→连通场景图"成熟工具。**
- **VTT importer**（Foundry VTT / Roll20 adventure importer）：确定性模板解析，仅认官方授权模组，零语义、零图谱。
- **AI-GM / solo-RPG 项目**：要么动态生成世界不读模组，要么只建空图/手填图。最接近我们的 `open-tabletop-gm` **明确把 LLM 抽取砍掉、只剩 manual + query-only**。

→ "自动从模组 PDF 抽出带边的连通图"正是公开领域都 **defer 的硬骨头**；我们做出来即领先。可借鉴的是**方法论 + 通用 KG 框架的机制**，不是 drop-in 工具。

## 1. 通用 LLM 知识图谱抽取框架（角度1）

| 项目 | 怎么抽边 | 对我们的借鉴 | License |
|---|---|---|---|

| **LlamaIndex PropertyGraphIndex** | 4 档 PathExtractor：Implicit/SimpleLLM/**DynamicLLM**/**SchemaLLM**（端点校验表，strict 只输出 schema 内边） | **P1**：用 SchemaLLMPathExtractor 的 (源类型,关系,目标类型) 校验逼出场景边；run-to-run 飘的根因就是无 schema 自由抽 | MIT |
| **Neo4j LLM Graph Builder** | 先建 Document→Chunk 词法图再抽实体关系；**内置 Entity Resolution 独立去重 pass** | **P3**：去重解耦成抽取后独立阶段（label+name→语义合并） | Apache-2.0 |
| **LangChain LLMGraphTransformer** | `allowed_relationships` 支持**三元组端点形式** `[("Scene","LEADS_TO","Scene")]` | **P1 最省事样板**：带端点签名的关系模板逼出 scene→scene 边 | MIT |

## 2. 叙事/场景图抽取（角度2，学术）

- **边不是"抽"是"算"（Gorinski & Lapata）** ⭐：不让模型直接吐 scene→scene link，而是建 **scene-character 二部图** + 带重启随机游走算场景间转移强度作边权。→ **实体作桥接节点，两场景共享实体即自动连边，零额外 LLM 调用**。
- **EDC 框架（抽取→定义→规范化）治 P3**：开放抽 triple → LLM 给实体写自然语言定义 → embed+LLM 复核合并。关键：只靠 embedding 阈值会误合，必须 LLM 二次确认。
- **STAGE / R² 治 P4**：叙事边分 6 类（Event-Role/Social/Inter-Event/Spatiotemporal/Object/Semantic）；因果边用递归 LLM 抽 + **贪心破环成 DAG**。我们的"场景转移边"= Spatiotemporal + Inter-Event 因果。

## 3. 长文档完整性/可靠性技巧（角度3，治 P2）

- **Gleaning 多轮补抽（GraphRAG/nano-graphrag）** ⭐：首遍抽 → 续抽 prompt「MANY entities were missed, add them（带上轮结果回灌，只补增量）」→ 判定 prompt「还有遗漏吗 YES/NO」→ `max_gleanings` 封顶。我们 **Pass A 骨架没有 gleaning 自检** = 3-vs-24 的根因。
- **TOC 锚定/层级抽取**：先建目录树框住深抽，覆盖变可枚举可核对；无 TOC 时 LLM 按语义边界生成 pseudo-TOC。
- 已知坑：续抽必须回灌上轮结果（GraphRAG #615 bug）；模型有 YES 偏好需 max 轮兜底。

## 4. TTRPG 专用（角度4）—— 最有用的设计理论

- **The Alexandrian — Node-Based Scenario Design + 三线索规则** ⭐⭐（最有用的新工具）：
  - **边的本质 = 线索（clue/lead）**：scene A→B 的边 = A 内一条指向 B 的可发现线索/通路（门/NPC 提示/物证/地图出口）。**把"抽 link"重述成"抽线索"，LLM 召回大涨**（治 P1）。
  - **倒置三线索规则 = 连通性验证器**：每节点 ≥3 出向 + ≥3 入向线索 → 全图鲁棒连通无孤岛。做成**抽取后 validator**：从入口 BFS，flag 孤岛/零入边/出向过少场景 → 既检测 P1 不连通、又当 P2 质量门（崩了就触发重抽）。
  - URL: thealexandrian.net/wordpress/7949 · /7985
- **CoC 结构分类**（linear/flowchart/onion/sandbox）：抽前先分类，不同结构不同边语义先验 + 形状预期（治 P2）。
- **open-tabletop-gm**（最像我们）：typed-edge 关系图，**每条边带 verbatim source-anchor**（抗幻觉，呼应我们 fail-closed）；但**LLM 抽取被砍只剩手填**——印证这是硬骨头。
- **envy-ai/ai_rpg**：Location 经 exits 显式互联成可导航图（边模型参考）；「区域 stub 先建、进入再深抽」与我们 P2/P5 一致；`SanitizedStringMap` 字符串归一作 P3 第一道筛。

## 5. 关系抽取 + 跨页指代消解（角度5，支撑 P1 边 + P3 去重）

- 关系抽取：REBEL（seq2seq 抽三元组）、OpenIE 6、document-level RE；LLM 做 RE 的现代做法 = schema 约束 + 端点签名。
- 指代/对齐：coreference resolution 跨页/跨章；entity linking；EDC 的 define→embed→LLM-confirm。

## 6. 落到我们身上：ROI 最高的三步（跨项目收敛共识）

1. **① 实体桥接边（零 LLM，用现有 `referenced_*_ids`）** —— 两场景共享实体即连边，立刻让图连通（Gorinski&Lapata）。
2. **② Pass A 加 gleaning 回环** —— 对照 TOC「还有哪些可玩单元没进骨架?YES/NO 补全」，治 3-vs-24 欠抽（GraphRAG）。
3. **③ 倒置三线索 validator** —— 入口 BFS + 出/入边阈值 + 孤岛检测，P1 检测 + P2 质量门 + 触发重抽（The Alexandrian）。

进阶：两遍先点后边（iText2KG）、边挂 source-anchor（open-tabletop-gm）、去重独立 pass（Neo4j/EDC）、边分类型破环（STAGE/R²）。
