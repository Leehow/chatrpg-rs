## 二、已建但仍"影子 / 契约 / 描述态"（类型在，未 load-bearing）

- **AssetEnvelope / AssetFacet / ExecutionTier**（`trpg-model/src/asset.rs`）：类型齐，但**无生产者**——
  parser（Rule Steward/Module Reader/Character Parser）仍出 ContextBlock/ScenarioNode/MaterialIndex，

- **ExecutionTier**：仅检定路由 + CLI coverage 用上。

## 四、核心判断与下一步

骨架基本搭齐，真实风险已**不是**"没开始"，而是"**影子层永不 load-bearing**（装饰性并行观察者）"。
检定 binding takeover 证明了"把影子逐条变 load-bearing"这条路可行（先证等价、再翻默认、留逃生阀）。

**下一竖切候选**（按杠杆）：① binding takeover 推广到 resource.delta / effect；② asset 生产者
（让 parser 出 AssetEnvelope，binding 才有真料绑）；③ TurnCommit 一等对象。
**心法**：别再铺契约宽度，把影子层逐条变 load-bearing；每条"先证逐字节等价、再翻默认、逃生阀保底"。

## 五、不要走回头路

- 不重做大一统规则编译器（之前失败是 TRPG 规则形态决定的，正确解是 late binding + execution tier + guided fallback）。
- 不让 runtime 出现 `ruleset_id.contains`；不让 GM Agent 决定机械结果；不把 transcript/memory 当状态权威；
  不为自动化牺牲 guided ruling；Playability 用绑定覆盖率表达而非"解析成功/失败"。
