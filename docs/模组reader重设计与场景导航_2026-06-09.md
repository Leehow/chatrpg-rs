# 模组抽取重设计 + 场景导航 —— 总报告（2026-06-09）

> 设计理念全程遵守：乐高/数据驱动**零硬编码** · agent-app **语义优先非关键词** · **fail-closed 永不编造/不乱跳** · 单一事实源 · 复用优先 · 文件 ≤400 行。

## 0. 一句话

把"模组上传后进游戏只看到免责声明、`ModuleGraph` 永远空"的旧管线，重做成 **agentic 渐进式结构化 reader（秒级首场景可玩 + 后台续抽）+ 模组场景导航（进游戏激活入口、叙事推进语义切换、到场深抽）**，并在 **CoC 沙盒 + Triangle 任务集两种结构、中/英两语种**真游戏真回合里端到端验证通过。

## 1. 模组 reader 重设计（spec/plan 见 `docs/superpowers/{specs,plans}/2026-06-09-module-reader-redesign*`）

旧痛点：`parse_module` 产出的 `ModuleGraph` 所有结构化字段恒为 `vec![]`、且无消费方；进游戏开场是前言而非游戏。

**6 阶段（subagent-driven，每 task spec+质量双审）：**
- **Phase 0 去栏交错（trpg-ingest）**：spike 发现头号瓶颈是 ingestion 双栏逐行交错（read_aloud 命脉）。新增 `decolumnize_layout_page`——复用已算的 `-layout` 文本按空白河切列、列内上→下、列间左→右；`merge_duotext_pages` 散文页改用去栏结果，检不出回退（fail-closed）。CJK 阈值 `MIN_PAGE_WIDTH=16`（char 计数对 CJK 视觉宽约 2x）。extractor tag bump `duotext2` 失旧缓存。
- **Phase 1 数据模型（trpg-model）**：`ScenarioNode` 加 extraction_status/page_start-end/referenced_*_ids；新枚举 `SceneExtractionStatus`/`ModuleContentClass`/`LinkType`，全 `#[serde(default)]` 向后兼容。复用 `ScenarioNode` 不造 `ModuleScene`，单一 `scenes` 列表 + 状态位（不引入 SceneStub）。
- **Phase 2 module_reader.rs（trpg-rule-agent）**：对标 `chargen_compile.rs` 的聚焦第二刀。Pass A 读 TOC+前言建全书骨架（语义选 `entry_node_id` 跳过前言/安全提示，页码从 `# Page N` 页锚抽）；Pass B 深抽首场景+依赖闭包。`parse_module` 门控 `TRPG_MODULE_READER` 委派、失败回退 vec![]。≤400 行（拆 `module_reader_loop.rs`）。
- **Phase 3 BP2/BP3 入库**：`module_static_blocks` 把分类内容转 ContextBlock——自定义规则→PinnedMiddle(BP2 常驻)、实体索引→DynamicTail(BP3)。复用现有 cache_zone 分桶，无新机制。
- **Phase 4 runtime 当前场景投影器**：`module_scene_blocks_for_turn` 按 scene_id 投影当前场景 deep 内容（read_aloud/gm_notes/在场 NPC + **links 出口**），SkeletonOnly 跳过交 materializer 降级。
- **Phase 5 后台续抽（trpg-api）**：`module_extract_continue` job 串行深抽剩余 SkeletonOnly 场景；核心抽成 `extract_module_scenes(only)` 供续抽 + 到场深抽复用。无持久化/重启续跑（spec §7 接受降级，靠 extraction_status 持久化 + 文本检索兜底）。

## 2. Spike 验证 + 时间记录

"Claude 当 reader 钻进壳" + 真实 reader（gpt-5.4-mini）在 3 个差异极大模组上实测：

| 模组 | 规则/语种 | 结构 | 骨架 | 最小可用单元耗时 |
|---|---|---|---|---|
| 血色公路 | CoC 中文 | sandbox+时间线 | 37 场景 | **~59-131s** |
| The Vault | Triangle 英文 | 任务集 | 16 场景 | ~109s |
| Homecoming | CPR 英文 | 线性 one-shot | 24 场景 | ~95s |

**结论：最小可用模组解析约 1-2 分钟**（Pass A 全书骨架 + Pass B 首场景深抽，gpt-5.4-mini，budget=8）—— 非秒级但远快于全量解析；优化方向"骨架先交付、深抽紧随"已留。

## 3. 场景导航（spec/plan 见 `docs/superpowers/{specs,plans}/2026-06-09-module-scene-navigation*`）

spike 后 e2e 暴露：P4 投影机制建好了，但**没人激活/切换当前场景**（start_session 不设 scene_id、CLI turn 恒 None）→ 模组越不过入口、P5 预抽场景不可达。

**5 组件（subagent 分波并行实现，Wave1/2 双审 Approved）：**
1. **持久化** `sessions.current_scene_id`（迁移 0026）+ db set/load_session_scene。
2. **入口激活** start_session(module) → load_module_graph → `module_entry_scene_id`（spine.entry_node_id→首 deep→scenes[0]）→ 设 current_scene_id。
3. **每回合载入** runtime `prepare_turn_context` 单点：scene_id 缺且有 module → 载 current_scene_id（DRY，CLI/API 共享）。
4. **P4 出口投影** `scene_node_to_blocks` 附加当前场景 links 出口标题（GM 知道能去哪）。
5. **语义切换** `scene_navigator`（LLM 从真实场景列表语义判定 moved/target_node_id，**fail-closed 默认不动**，`validate_transition` 校验 target 真实存在）+ 到场深抽（复用 `extract_module_scenes(only=target)`）。

**关键缺口补上**：scene_navigator 原只接 API `turn_postprocess`；本次也接进 CLI `run_turn_once`（改 pub + 末尾 fail-closed 调用）—— **API/CLI 两条回合路径都语义切换场景**。

## 5. 关键发现 / 修复

- **瓶颈在 ingestion 不在 reader**：双栏交错是 read_aloud 命脉，先去栏再 reader。
- **"前言陷阱"**：reader 早期把入口选成"前言/安全提示"页 → 加语义 `entry_node_id`（非关键词黑名单），入口 0/3→3/3 全对带真念白。
- **页码必从 `# Page N` 页锚抽**（不依赖 TOC 页码）→ Vault/Homecoming 抽到，血色公路 holdout（碎片化 units，降级兜底）。
- **source_id 单一事实源**：续抽/到场深抽从 `bundle.source_index.sources[0].source_id` 推导（= parse_module 写 units 的同一 id），非臆造。
- **图片-only 属性卡**（Homecoming p17-26 缺失）→ bp3 stub + 标记，绝不编造数值。
- **CLI scene_navigator 缺口**：补进 run_turn_once，两路径统一。
