# R2 实施计划：统一 Need 总线（回合内数据获取收口 typed Need + NeedBus）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把回合内 5 类数据获取（规则/材料/场景/实体/参数）统一为 `bus.emit(Need)` + `resolve_all()`，RuleSteward 成唯一 rule authority、SearchService 退成 resolver 内部纯 retriever，回合内 kernel 不再直连 search/service。

**Architecture:** 新 crate `trpg-need`（`Need` enum + `NeedResolver` trait + `NeedBus`，低层仅依赖 trpg-model）；resolver 落 trpg-runtime 包既有 service 为薄 adapter；`prepare_turn_context` 的"数据获取类"块装配改为 emit Need→resolve_all→并入 blocks（"状态投影类"块如 ability/rule_binding/world_time/object/frame/referee/contest 原样不动）；同步解析；分阶段（RuleNeed 先行验等价 → 逐迁 Scene/Material/Param/Entity → 收口删直连）。决定性收敛但分阶段落地，合并前过验证闸（context 块等价 + 两 transport 真库 live + 零回归 + 缓存稳定）。

**Tech Stack:** Rust, async-trait, tokio, trpg-model 类型（ContextBlock/SourceRef），RuleStewardAgent::assist（无 LLM 确定性检索）。前置 spec：`docs/superpowers/specs/2026-06-14-r2-need-bus-design.md`。

  ```rust
  //! R2 unified Need bus: typed turn-scoped data-acquisition requests + a kind-routed
  //! resolver registry. Low-level crate — depends only on trpg-model. Resolvers (which
  //! wrap runtime services) live in trpg-runtime, not here.
  use trpg_model::{ContextBlock, SourceRef};

  // RuleNeed/RuleNeedKind are canonically defined in trpg-model and consumed by
  // trpg-rule-agent via `use trpg_model::*`. We re-export the SAME type (single
  // definition, zero duplication) so callers can refer to `trpg_need::RuleNeed`.
  pub use trpg_model::{RuleNeed, RuleNeedKind};

  /// Discriminant used to route a Need to the resolver that claims that kind.
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum NeedKind {
      Rule,
      Material,
      Scene,
      Entity,
      Parameter,
  }

  /// Turn-scoped addressing shared by every Need payload. No per-ruleset fields:
  /// all ids are opaque strings filled by the turn pipeline.
  #[derive(Debug, Clone)]
  pub struct NeedScopes {
      pub ruleset_id: String,
      pub module_id: Option<String>,
      pub session_id: String,
      pub turn_id: String,
      pub scene_id: Option<String>,
  }

  /// A typed data-acquisition request emitted during turn-context assembly.
  #[derive(Debug, Clone)]
  pub enum Need {
      Rule(RuleNeed),
      Material(MaterialNeed),
      Scene(SceneNeed),
      Entity(EntityNeed),
      Parameter(ParameterNeed),
  }

  impl Need {
      pub fn kind(&self) -> NeedKind {
          match self {
              Need::Rule(_) => NeedKind::Rule,
              Need::Material(_) => NeedKind::Material,
              Need::Scene(_) => NeedKind::Scene,
              Need::Entity(_) => NeedKind::Entity,
              Need::Parameter(_) => NeedKind::Parameter,
          }
      }
  }

  #[derive(Debug, Clone)]
  pub struct MaterialNeed {
      pub scopes: NeedScopes,
      pub user_input: Option<String>,
  }

  #[derive(Debug, Clone)]
  pub struct SceneNeed {
      pub scopes: NeedScopes,
  }

  #[derive(Debug, Clone)]
  pub struct EntityNeed {
      pub scopes: NeedScopes,
      pub entity_hint: Option<String>,
  }

  #[derive(Debug, Clone)]
  pub struct ParameterNeed {
      pub scopes: NeedScopes,
      pub actor_id: Option<String>,
      pub current_input: Option<String>,
  }

  /// What a resolver returns: context blocks to merge + source refs for grounding.
  /// State mutations (e.g. NPC synth writing sheet_json) stay as service-internal
  /// side effects inside the resolver's wrapped service — they do NOT travel here.
  #[derive(Debug, Default)]
  pub struct NeedOutcome {
      pub blocks: Vec<ContextBlock>,
      pub source_refs: Vec<SourceRef>,
  }

  /// One resolver claims exactly one NeedKind and turns a Need into a NeedOutcome.
  #[async_trait::async_trait]
  pub trait NeedResolver: Send + Sync {
      fn kind(&self) -> NeedKind;
      async fn resolve(&self, need: &Need) -> anyhow::Result<NeedOutcome>;
  }

  /// Kind-routed registry. Collects emitted Needs, then resolves the whole batch.
  pub struct NeedBus {
      resolvers: Vec<Box<dyn NeedResolver>>,
      pending: Vec<Need>,
  }

  impl Default for NeedBus {
      fn default() -> Self { Self::new() }
  }

  impl NeedBus {
      pub fn new() -> Self {
          Self { resolvers: Vec::new(), pending: Vec::new() }
      }

      pub fn register(&mut self, r: Box<dyn NeedResolver>) {
          self.resolvers.push(r);
      }

      pub fn emit(&mut self, need: Need) {
          self.pending.push(need);
      }

      /// Drain pending needs and resolve each via the resolver whose kind matches.
      /// fail-closed: an unclaimed kind warns and is skipped (no outcome); a resolver
      /// Err warns and contributes an empty NeedOutcome — the turn is never aborted.
      pub async fn resolve_all(&mut self) -> Vec<NeedOutcome> {
          let needs = std::mem::take(&mut self.pending);
          let mut outcomes = Vec::with_capacity(needs.len());
          for need in &needs {
              let want = need.kind();
              let Some(resolver) = self.resolvers.iter().find(|r| r.kind() == want) else {
                  tracing::warn!(?want, "no NeedResolver claims this need kind; skipping (fail-closed)");
                  continue;
              };
              match resolver.resolve(need).await {
                  Ok(outcome) => outcomes.push(outcome),
                  Err(err) => {
                      tracing::warn!(error = %err, ?want, "NeedResolver failed; empty outcome (fail-closed)");
                      outcomes.push(NeedOutcome::default());
                  }
              }
          }
          outcomes
      }
  }
  ```
  说明：契约的 `resolve_all` 注释提到「可并发(join_all)」；本任务先落确定性顺序版（满足 fail-closed/路由测试，且 borrow `&self.resolvers` + `&mut self` 取 pending 最简）。并发化是 resolver 迁移阶段（后续任务段）的可选优化，不在 Task 1 范围——顺序版语义即满足验收，留并发为后续 join_all 改造点（不破签名）。

// crates/trpg-runtime/src/scene_need_resolver.rs
use async_trait::async_trait;
use trpg_db::Db;
use trpg_model::{ContextBlock, ModuleGraph, ProjectBundle, RuntimeState,
                 ScenarioNode, SceneExtractionStatus};
use trpg_need::{Need, NeedKind, NeedOutcome, NeedResolver, SceneNeed};

use crate::scene_projection::{resolve_turn_scene_id, scene_node_to_blocks};

/// 纯函数包装：给定已选中的 node + graph.npcs + graph.scenes，
/// 产出与 scene_node_to_blocks 字节等价的块。单独提取便于测试隔离。
pub(crate) fn resolve_scene_blocks(
    module_id: &str,
    node: &ScenarioNode,
    npcs: &[serde_json::Value],
    scenes: &[ScenarioNode],
) -> Vec<ContextBlock> {
    let blocks = scene_node_to_blocks(module_id, node, npcs, scenes);
    if !blocks.is_empty() {
        tracing::info!(
            target: "module_scene",
            module_id,
            scene = %node.title,
            "SceneNeedResolver: projected current module scene into turn context"
        );
    }
    blocks
}

/// fail-closed 空路径：无 module_id 时返回空 Vec，不 panic。
pub(crate) fn resolve_scene_blocks_no_module() -> Vec<ContextBlock> {
    Vec::new()
}

/// 从 ModuleGraph 选出当前场景节点：
/// 显式 scene_id 优先，缺失/不匹配则回退首个 DeepExtracted（入口场景）。
/// fail-closed：无匹配 → None。与 `module_scene_blocks_for_turn` 逻辑完全相同。
fn pick_scene_node<'g>(
    graph: &'g ModuleGraph,
    scene_id: Option<&str>,
) -> Option<&'g ScenarioNode> {
    scene_id
        .and_then(|sid| graph.scenes.iter().find(|s| s.node_id == sid))
        .or_else(|| {
            graph
                .scenes
                .iter()
                .find(|s| s.extraction_status == SceneExtractionStatus::DeepExtracted)
        })
}

/// SceneNeedResolver: 包 module_scene_blocks_for_turn 的异步 DB 部分。
/// 薄 adapter，零检索逻辑：DB 取图 → pick_scene_node → resolve_scene_blocks。
pub struct SceneNeedResolver {
    pub db: Db,
}

#[async_trait]
impl NeedResolver for SceneNeedResolver {
    fn kind(&self) -> NeedKind {
        NeedKind::Scene
    }

    async fn resolve(&self, need: &Need) -> anyhow::Result<NeedOutcome> {
        let scene_need = match need {
            Need::Scene(s) => s,
            _ => return Ok(NeedOutcome::default()),
        };

        let module_id = match scene_need.scopes.module_id.as_deref() {
            Some(id) if !id.trim().is_empty() => id,
            _ => return Ok(NeedOutcome::default()), // fail-closed: 无 module_id
        };

        // 复用 module_scene_blocks_for_turn 的 project 成员校验逻辑：
        // 仅当 module 隶属本 project 时才继续（prevent cross-project leakage）。
        let project_ok = scene_need.project_module_ids.iter().any(|id| id == module_id);
        if !project_ok {
            tracing::warn!(module_id, "SceneNeedResolver: module not in project, skipping");
            return Ok(NeedOutcome::default());
        }

        let Some(graph) = self.db.load_module_graph(module_id).await? else {
            return Ok(NeedOutcome::default()); // fail-closed: 图谱缺失
        };

        let Some(node) = pick_scene_node(&graph, scene_need.scopes.scene_id.as_deref()) else {
            return Ok(NeedOutcome::default()); // fail-closed: 无可用场景
        };

        let blocks = resolve_scene_blocks(module_id, node, &graph.npcs, &graph.scenes);
        Ok(NeedOutcome { blocks, source_refs: vec![] })
    }
}
```

use trpg_time::WorldTimeService;

pub struct MaterialNeedResolver {
    db: Db,
}

impl MaterialNeedResolver {
    pub fn new(db: Db) -> Self {
        Self { db }
    }

    async fn world_tick(&self, session_id: &str) -> i64 {
        WorldTimeService::new(self.db.clone())
            .current_time(session_id)
            .await
            .map(|t| t.world_tick)
            .unwrap_or_default()
    }
}

#[async_trait]
impl NeedResolver for MaterialNeedResolver {
    fn kind(&self) -> NeedKind {
        NeedKind::Material
    }

    async fn resolve(&self, need: &Need) -> Result<NeedOutcome> {
        let Need::Material(m) = need else {
            return Ok(NeedOutcome::default());
        };
        let world_tick = self.world_tick(&m.scopes.session_id).await;
        let block: ContextBlock = MaterializationService::from_env(
            self.db.clone(),
            // SearchService 不影响 materialization_context_block（只读 DB）；
            // 传 None 与 from_env 的 search=None 分支等价（context_block 无搜索调用）。
            None,
        )
        .materialization_context_block(&m.scopes.session_id, world_tick)
        .await?;

        Ok(NeedOutcome {
            blocks: vec![block],
            source_refs: vec![],
        })
    }
}

  pub enum NeedKind { Rule, Material, Scene, Entity, Parameter }

  #[derive(Debug, Clone)]
  pub struct NeedScopes {
      pub ruleset_id: String,
      pub module_id: Option<String>,
      pub session_id: String,
      pub turn_id: String,
      pub scene_id: Option<String>,
  }

      pub scopes: NeedScopes,
      pub actor_id: Option<String>,
      pub current_input: Option<String>,
  }

  #[derive(Debug, Clone)]
  pub enum Need {
      // 其余 variant 由 Tasks 1-4 建；本任务只需 Parameter
      Parameter(ParameterNeed),
      // Tasks 1-4 所建 variant 占位（独立执行时补全）:
      Rule(serde_json::Value),
      Material(serde_json::Value),
      Scene(serde_json::Value),
      Entity(serde_json::Value),
  }

  impl Need {
      pub fn kind(&self) -> NeedKind {
          match self {
              Need::Rule(_) => NeedKind::Rule,
              Need::Material(_) => NeedKind::Material,
              Need::Scene(_) => NeedKind::Scene,
              Need::Entity(_) => NeedKind::Entity,
              Need::Parameter(_) => NeedKind::Parameter,
          }
      }
  }

  #[derive(Debug, Default)]
  pub struct NeedOutcome {
      pub blocks: Vec<ContextBlock>,
      pub source_refs: Vec<SourceRef>,
  }

  #[async_trait::async_trait]
  pub trait NeedResolver: Send + Sync {
      fn kind(&self) -> NeedKind;
      async fn resolve(&self, need: &Need) -> anyhow::Result<NeedOutcome>;
  }

  pub struct NeedBus {
      resolvers: Vec<Box<dyn NeedResolver>>,
      pending: Vec<Need>,
  }

  impl NeedBus {
      pub fn new() -> Self { Self { resolvers: vec![], pending: vec![] } }
      pub fn register(&mut self, r: Box<dyn NeedResolver>) { self.resolvers.push(r); }
      pub fn emit(&mut self, need: Need) { self.pending.push(need); }
      pub async fn resolve_all(&mut self) -> Vec<NeedOutcome> {
          let mut out = Vec::new();
          for need in self.pending.drain(..) {
              let kind = need.kind();
              let resolver = self.resolvers.iter().find(|r| r.kind() == kind);
              match resolver {
                  None => { tracing::warn!(kind = ?kind, "NeedBus: no resolver for kind, skipping"); }
                  Some(r) => match r.resolve(&need).await {
                      Ok(outcome) => out.push(outcome),
                      Err(e) => { tracing::warn!(error = %e, kind = ?kind, "NeedBus: resolver failed, empty outcome (fail-closed)"); out.push(NeedOutcome::default()); }
                  }
              }
          }
          out
      }
  }

          let world_tick = WorldTimeService::new(self.db.clone())
              .current(&need.scopes.session_id)
              .await
              .map(|t| t.world_tick)
              .unwrap_or_default();

          let service = RuntimeParameterService::new(self.db.clone());
          let actor_id = need.actor_id.as_deref().unwrap_or("pc.current");

                  actor_id,
                  ActorKind::PlayerCharacter,
                  world_tick,
              )
              .await;

          // live 派生刷新（等价旧 :1785）
          let _ = self.refresh_live_derived(&need.scopes.session_id, actor_id).await;

              .db
              .list_active_state_frames(&need.scopes.session_id, 1)
              .await
              .map(|v| !v.is_empty())
              .unwrap_or(false);

- [ ] **Step 3: 实现 `EntityNeedResolver`（薄 adapter，包 `ensure_npc_parameter`）**

  在 `crates/trpg-runtime/src/lib.rs`（`RuntimeEngine` impl 块之外，文件末尾前）新增：

  ```rust
  /// EntityNeedResolver：包 npc_synth/ensure_npc_parameter 的 Need 总线 adapter。
  /// 核心语义是**副作用**（写 NPC 卡 sheet_json + 刷 mechanical_profile），
  /// resolve() 返回空 blocks（不产 context 块）。门由 TRPG_NEED_BUS_ENTITY 控制。
  pub struct EntityNeedResolver {
      engine: std::sync::Arc<RuntimeEngine>,
  }

  impl EntityNeedResolver {
      pub fn new(engine: std::sync::Arc<RuntimeEngine>) -> Self { Self { engine } }
  }

  #[async_trait::async_trait]
  impl trpg_need::NeedResolver for EntityNeedResolver {
      fn kind(&self) -> trpg_need::NeedKind { trpg_need::NeedKind::Entity }

      async fn resolve(&self, need: &trpg_need::Need) -> anyhow::Result<trpg_need::NeedOutcome> {
          let trpg_need::Need::Entity(e) = need else {
              return Ok(trpg_need::NeedOutcome::default());
          };
          // entity_hint 必须存在（prepass 填 target.actor_id）；否则 fail-closed。
          let actor_id = match e.entity_hint.as_deref() {
              Some(id) if !id.is_empty() => id,
              _ => {
                  tracing::warn!(target: "entity_need_resolver", "EntityNeed missing entity_hint — skipping synthesis");
                  return Ok(trpg_need::NeedOutcome::default());
              }
          };
          // entity_hint 编码为 "{actor_id}|{bucket}|{param}|{check_context}" 或退回
          // 到仅有 actor_id 时跳过现搓（caller 应透传完整 hint）。
          let parts: Vec<&str> = actor_id.splitn(4, '|').collect();
          let (actor_id_str, bucket, param, check_ctx) = match parts.as_slice() {
              [aid, bkt, prm, ctx] => (*aid, *bkt, *prm, *ctx),
              _ => {
                  tracing::warn!(target: "entity_need_resolver",
                      hint = actor_id, "EntityNeed hint不含足够字段(期望 actor_id|bucket|param|ctx) — 跳过");
                  return Ok(trpg_need::NeedOutcome::default());
              }
          };
          let persona = npc_synth::NpcPersona {
              actor_id: actor_id_str.to_string(),
              // name/prose 无法从 hint 还原；现搓 T1/T2/T3 不依赖它们做路由，
              // T3 persona-judge 用到时 prose 为空则 LLM 产默认判断（仍 fail-closed）。
              name: actor_id_str.to_string(),
              prose: String::new(),
          };
          // 副作用：写卡（等价于 prepare_binding 内的 ensure_npc_parameter 调用）。
          // fail-closed：Ok(None)=门关/无LLM/无卡 → 空 outcome；Err → warn + 空 outcome。
          match self.engine.ensure_npc_parameter(
              &e.scopes.session_id, &e.scopes.ruleset_id,
              &persona, bucket, param, check_ctx,
          ).await {
              Ok(Some(_)) => {
                  tracing::info!(target: "entity_need_resolver",
                      actor_id = actor_id_str, bucket, param, "NPC param synthesized via NeedBus");
              }
              Ok(None) => {
                  tracing::info!(target: "entity_need_resolver",
                      actor_id = actor_id_str, "synthesis unavailable (gate off / no LLM / no card) — ok");
              }
              Err(err) => {
                  tracing::warn!(target: "entity_need_resolver",
                      error = %err, actor_id = actor_id_str, "synthesis failed (fail-closed, turn continues)");
              }
          }
          // blocks 恒空——副作用为主，context 装配不依赖 EntityNeed 产块。
          Ok(trpg_need::NeedOutcome::default())
      }
  }
  ```

- [ ] **Step 9: 缓存稳定性验证（只改玩家输入只动 dynamic_hash）**

  对齐 R1 缓存锚手法：同一会话连续两回合，第一回合缓存相关字段（prefix/pinned 不变），第二回合仅变 user_input，断言 prefix_hash 和 pinned_hash 不变，只有 dynamic_hash 变动。

  ```bash
  cd /Users/haoli/leehow/code/chatrpgv2/chatrpg-rs-v1.20-formula
  DATABASE_URL=postgres://chatrpg:chatrpg@localhost:54347/chatrpg \
  TRPG_LLM_PROVIDER=openai TRPG_LLM_BASE_URL=http://127.0.0.1:18888/v1 \
  TRPG_LLM_API_KEY=relay TRPG_LLM_MODEL=gpt-5.5 TRPG_LLM_SEND_TEMPERATURE=false \
  TRPG_DATA_DIR=./data \
  ./target/debug/trpg turn \
    --ruleset call_of_cthulhu_7e \
    --module call_of_cthulhu_7e.document \
    --input "我在酒吧里坐下，点了一杯饮料" \
    --stream-format jsonl \
  2>&1 | tee /tmp/r2_cache_turn1.jsonl

  # 提取本回合 session_id 和 turn_id（从 DB 查最新）
  docker exec chatrpg-postgres-rulesets psql -U chatrpg -d chatrpg \
    -c "SELECT session_id, turn_id, compiled_context_hash FROM context_watermarks
        ORDER BY updated_at DESC LIMIT 1;" \
    | tee /tmp/r2_cache_turn1_hash.txt
  ```

  记录 `compiled_context_hash`（= `prefix_hash[:20]:pinned_hash[:20]` 的前缀）作为 HASH_TURN1。

  然后在同一 session 跑第二回合（只改玩家输入）：
  ```bash
  SESSION_ID=$(docker exec chatrpg-postgres-rulesets psql -U chatrpg -d chatrpg -t \
    -c "SELECT session_id FROM context_watermarks ORDER BY updated_at DESC LIMIT 1;" \
    | tr -d ' \n')

  DATABASE_URL=postgres://chatrpg:chatrpg@localhost:54347/chatrpg \
  TRPG_LLM_PROVIDER=openai TRPG_LLM_BASE_URL=http://127.0.0.1:18888/v1 \
  TRPG_LLM_API_KEY=relay TRPG_LLM_MODEL=gpt-5.5 TRPG_LLM_SEND_TEMPERATURE=false \
  TRPG_DATA_DIR=./data \
  ./target/debug/trpg turn \
    --ruleset call_of_cthulhu_7e \
    --module call_of_cthulhu_7e.document \
    --session-id "$SESSION_ID" \
    --input "我问酒保最近镇上有什么怪事" \
    --stream-format jsonl \
  2>&1 | tee /tmp/r2_cache_turn2.jsonl

  docker exec chatrpg-postgres-rulesets psql -U chatrpg -d chatrpg \
    -c "SELECT compiled_context_hash FROM context_watermarks
        WHERE session_id='$SESSION_ID' ORDER BY updated_at DESC LIMIT 1;" \
    | tee /tmp/r2_cache_turn2_hash.txt
  ```

  手动断言：
  ```bash
  # 提取两回合的 cache_key（格式: vis_hash[:20]:prefix_hash[:20]:pinned_hash[:20]）
  HASH1=$(grep -oP '\w{20}:\w{20}:\w{20}' /tmp/r2_cache_turn1_hash.txt | head -1)
  HASH2=$(grep -oP '\w{20}:\w{20}:\w{20}' /tmp/r2_cache_turn2_hash.txt | head -1)
  echo "turn1 hash: $HASH1"
  echo "turn2 hash: $HASH2"

  # prefix 段（第1段）和 pinned 段（第2段）应相同；dynamic 段（BP3 含 current_input）会变
  PREFIX1=$(echo $HASH1 | cut -d: -f1)
  PREFIX2=$(echo $HASH2 | cut -d: -f1)
  PINNED1=$(echo $HASH1 | cut -d: -f2)
  PINNED2=$(echo $HASH2 | cut -d: -f2)
  [ "$PREFIX1" = "$PREFIX2" ] && echo "PASS: prefix_hash stable" || echo "FAIL: prefix_hash changed"
  [ "$PINNED1" = "$PINNED2" ] && echo "PASS: pinned_hash stable" || echo "FAIL: pinned_hash changed"
  ```

  **注意**：`compiled_context_hash` 仅含 prefix+pinned 片段（不含 dynamic_hash，见 `crates/trpg-runtime/src/lib.rs:1942`），故两回合 hash 相同说明 BP1+BP2 块在只变输入的情况下内容未漂移，即缓存稳定。若 prefix/pinned 片段变化，说明某 resolver 在迁移前后产出了不同块 ID 或块内容（等价性破坏），需回对应 Task 修复。
