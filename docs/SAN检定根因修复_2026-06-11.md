# SAN 检定根因修复报告（2026-06-11）

J2 CoC 血色公路 SAN 采样评测（session_9045a3c4，13 回合 0 contracts / 0 rolls / 0 agent_tool_calls）的根因调查与修复，全量落地并复测通过。

## 根因（多层叠加）

**评测运行事故：**
1. **角色卡串台**：评测 runner 的 play 进程重启导致角色卡（SAN 60）绑到孤儿 session（94bf），实际游玩 session 的 `pc.current` 是无数值 stub。GM 面对无参数角色 + prompt 明令"不编造目标值" → 理性回避一切机械检定。
2. **运行环境错位**：评测 cwd 在 chatrpg-rs-v1.16.2（极简 .env + 旧 data 目录），跑的却是 v1.20-formula 二进制。`dotenvy` 按 cwd 加载。

**结构性缺口（环境正确也不会触发 SAN）：**
3. **被动刺激→GM 发起检定无任何强制通路**：kernel 目录 `sanity_roll_and_loss` 的 when_to_use 写得对但 `hooks:[]`；watcher 无"叙事内容命中条目语义"触发器；sanity 轨 on_outcome 只在 check 结算后触发；named_check 只路由玩家显式宣告（且属旧编排路径）。
4. **事后 verifier 纯 substring_scan**，且 MissingCheck 只进勘误统计（不像 InventedEffect 成为阻塞债务）；waive 零约束。
5. **downtime frame 泄漏**：exit_mode 的退出义务无确定性闭合事件，无可结算项时只能 waive → frame 永久 active → 后续恐怖回合全在幕间姿态下裁定。
6. **可观测性缺口**：GM loop 的 dispatch 路径不写 agent_tool_calls（只有骰子路径写），评测无法对账。
